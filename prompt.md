# Бриф на сборку сайта

Задание для агента, который будет собирать сайт. Читать вместе с `DESIGN-SYSTEM.md`,
`PRODUCT.md`, `PROJECT-KIKI-TOONY.md`. Там, где этот файл противоречит им, — **прав этот
файл**: он написан позже и отражает уточнённую цель.

---

## 1. Одним абзацем

Одностраничный сайт-визитка **анимационной студии без имени**, которая делает короткие
детские мультики с помощью AI. Задача сайта — за 10–15 секунд показать уровень работ и
увести человека в WhatsApp. На странице **ровно одна кнопка** — связь через WhatsApp.
Сайт короткий: на десктопе умещается в один экран, на мобильном — максимум один скролл.
Язык сайта — **английский** (контент канала англоязычный, русской версии нет).

## 2. Цель

**Единственная бизнес-цель: входящие заявки на производство мультиков.** Человек, который
ищет исполнителя под свой проект (бренд-менеджер, продюсер детского продукта, издатель,
агентство), заходит, видит работы, нажимает кнопку и пишет в WhatsApp.

Всё, что не ведёт к нажатию этой кнопки, с сайта убирается. Подписки на YouTube,
просмотры, охваты, рассказ об авторе, форма обратной связи, почта, соцсети — **не цели и
не блоки этого сайта**.

## 3. Позиционирование (важное изменение к `PRODUCT.md`)

`PRODUCT.md` описывает сайт как продающий **конкретного автора-креатора**. Это отменяется.

Новое позиционирование:

- Мы — **студия**. Не конкретный человек, не персональное портфолио.
- **Названия у студии нет.** Никакого выдуманного нейминга, логотипа, вордмарка,
  аббревиатуры. Говорим «we», а не «I» и не «<Studio Name>».
- **Kiki Toony — это работа в портфолио, а не бренд сайта.** Канал показывается как
  доказательство уровня и как пример серии, а не как продукт, на который надо подписаться.
- Мы делаем мультики **с помощью AI** — это заявляется прямо и как преимущество: скорость,
  повторяемость стиля, любая тема. Это подтверждённый факт (в `PROJECT-KIKI-TOONY.md` §5
  он помечен `[?]` — снимаем пометку, автор подтвердил).
- Что продаём: **переносимость формулы**. Персонаж и стиль держатся серией, тема —
  переменная, и она может быть темой заказчика.

> Развилка, которую стоит держать в голове (решает владелец, сайт можно собрать в любом
> варианте): безымянная студия даёт меньше доверия, чем названный автор, а «сделано с
> помощью AI» для части покупателей — плюс (скорость, цена), для части — минус (качество,
> права). Формулировки в блоке 5 написаны так, чтобы AI подавался через выгоду заказчика,
> а не как самоцель.

## 4. Целевое действие

**Одна кнопка. Одна ссылка. Один WhatsApp.**

- Кнопка ведёт на бота в WhatsApp (`https://wa.me/<номер>?text=<преднабранный текст>`
  или ссылка на бота — точный URL см. §11, он ещё не предоставлен).
- Стиль: `Primary` из `DESIGN-SYSTEM.md` §3.3 — заливка `--acc-coral`, текст `--cream-50`,
  радиус `--r-full`, паддинг 18/34. Плюс приём «dashed halo» оттуда же.
- Текст кнопки: по-английски, действие + канал, например `Message us on WhatsApp`.
  Иконка WhatsApp — inline SVG, слева от текста.
- `target="_blank"`, `rel="noopener"`.
- Рядом — рукописная подпись `--font-hand` со стрелкой (приём из рефа 4), 2–4 слова,
  снимающая барьер: например `usually reply same day`. **Не обещать сроки производства,
  ставки и условия** — это запрещено (§10).
- На десктопе кнопка стоит в герое, под заголовком. На мобильном — **дополнительно
  залипающая** внизу экрана (`position: sticky`/`fixed`, safe-area-inset), чтобы она была
  видна всегда, в том числе во время просмотра галереи.
- Ни одной другой кнопки на странице. Карточки галереи — это ссылки на медиа, они не
  оформляются как кнопки и визуально не конкурируют с CTA.

## 5. Структура страницы

Ритм из `DESIGN-SYSTEM.md` §2.6 (9 блоков: nav → hero → галерея → about → слайдер →
how it works → numbers → CTA → footer) **не применяется**. Он рассчитан на длинный
одностраничник. Здесь — три зоны:

```
┌─────────────────────────────────────────────────────┐
│  (без nav — навигировать некуда)                    │
│                                                     │
│  кикер: what we do                                  │
│  H1 в 2 строки, одно слово акцентным курсивом       │
│  lead в 2 строки, узкая колонка                     │
│  [ ● Message us on WhatsApp ]   ↖ рукописная подпись│
│                                                     │
│  строка-факты: 18 films · ~2.5 min · any topic      │
├─────────────────────────────────────────────────────┤
│  ГАЛЕРЕЯ — full-bleed, горизонтальная,              │
│  уезжает за оба края экрана                         │
│  [ 16:9 ] [ 16:9 ] [ 16:9 ] [ 16:9 ] [ 16:9 ]  →    │
└─────────────────────────────────────────────────────┘
```

Требования к зонам:

**Герой.** Заголовок про то, что мы делаем и для кого, а не про канал. Смысл: «короткие
детские мультики под ваш бренд, любая тема, единый стиль, собрано на AI». Lead — 2 строки,
не больше, максимум ~55 слов на всю страницу текста суммарно. Акцентный курсив
`--acc-coral` на 1–2 словах заголовка (приём из рефа 1).

**Строка фактов.** Только про объём и формат, никаких аудиторных цифр:
`18 films · 2:18–2:38 each · 4 themes · one weekly release`. Мелкий кегль (`small`),
разделители — точки, `--ink-500`.

**Галерея.** Единственный медийный блок и главный аргумент. Full-bleed лента обложек,
обрезанная краями экрана (ключевой приём всех четырёх референсов). По клику — переход на
ролик на YouTube в новой вкладке. Механика — из `DESIGN-SYSTEM.md` §3.6: маски по краям,
драг мышью, свайп, `scroll-snap-type: x proximity`, автопрокрутка-marquee с паузой на
hover, отключение автопрокрутки при `prefers-reduced-motion`.

**Чего на странице нет:** nav, блока «об авторе», слайдера плейлистов, ленты шагов
«как это делается», блока с цифрами-достижениями, футера со ссылками на площадки, формы,
почты, соцкнопок, cookie-баннера. Внизу допустим один служебный микро-ряд 13px
`--ink-300`: год + `made with AI`. Не больше.

### 6.3 Важное расхождение с дизайн-системой

`DESIGN-SYSTEM.md` §3.5–3.6 описывает **вертикальные карточки 9:16**. Реальные обложки —
**горизонтальные 16:9**. Кадрировать их в вертикаль нельзя: композиция обложек построена
на маскоте по центру и крупном леттеринге сверху, при обрезке в 9:16 разрушается и то, и
другое.

**Решение:** карточки галереи — 16:9, ширина 320–420px на десктопе. Веер с поворотом
±2–6° из §3.5 при таком формате читается грязно — вместо него ровная лента с лёгкой
параболической дугой по `translateY` (края опускаются на ~20px) и hover
`scale(1.03)` + тень `--sh-3`. Радиус `--r-lg`, `overflow: hidden`.

Оверлей карточки — из §3.5: градиент `transparent → rgba(22,19,14,.6)` снизу, внутри
название ролика и длительность, `--cream-50`.

## 8. Адаптив

Обязателен, мобильная версия — не второстепенная: часть покупателей открывает ссылку с
телефона.

| Брейкпоинт | Поведение |
|---|---|
| ≥1280px | Герой `100dvh`, галерея внизу экрана, видно ~2.5 карточки, лента уходит за правый край |
| 768–1279px | Кегли по мобильной колонке шкалы §2.3, карточки 280–320px |
| <768px | Текст по левому краю или по центру (единообразно), H1 44px, галерея — горизонтальный свайп с `scroll-snap`, видно 1.15 карточки; **CTA залипает внизу**; поля 20px; рамка страницы убирается; закорючки — одна или ноль |

Отдельно проверить:

- Ландшафтную ориентацию телефона — герой не должен ломаться на низкой высоте
  (использовать `dvh`, не `vh`; проверить, что CTA не уезжает под адресную строку).
- Тач-цели ≥44×44px.
- Общая высота на мобильном — **максимум один экран прокрутки**, идеально: герой в первом
  экране целиком, галерея приоткрыта снизу и досматривается свайпом вбок.

## 9. Технические требования

- Стек — как в `PRODUCT.md`: **статичный HTML + CSS + vanilla JS, без сборщика**.
  Открывается двойным кликом по файлу, разворачивается на любом хостинге.
- Один `index.html`, один `styles.css`, один `script.js`. Ассеты — в `assets/`.
- **Обложки обязательно пережать перед выкладкой.** Сейчас `material/` весит 50 МБ,
  `обложка.png` одна — 12 МБ. Целевой вес страницы со всеми обложками — **до 1.5 МБ**.
  Формат: WebP с JPEG-фолбэком через `<picture>`, ширина под карточку ×2 (максимум 840px),
  качество 80.
- `loading="lazy"` на всех карточках кроме первых двух, у первых — `fetchpriority="high"`.
- Явные `width`/`height` на изображениях, чтобы не было сдвига layout.
- Шрифты — локально в `assets/fonts/`, `font-display: swap`. Если General Sans недоступен —
  Poppins или Switzer (альтернативы указаны в §2.2 ДС).
- Семантика и доступность: одна `h1`, `alt` у каждой обложки с названием ролика, у CTA —
  различимое имя ссылки, фокус-стили видимые, контраст текста ≥4.5:1.
- `prefers-reduced-motion` — все анимации из §4 ДС сводятся к `opacity`.
- Мета: `title`, `description`, Open Graph (`og:image` — обложка Summer Fruits или
  Colours, они самые «продающие»), favicon.
- Кроссбраузерно: Safari (в т.ч. iOS), Chrome, Firefox. Проверить `backdrop-filter`,
  `mask-image`, `dvh` — под них нужны фолбэки.

## 10. Контентные запреты

Из `PRODUCT.md` §«Ограничения», действуют без исключений:

- **Не выводить просмотры и подписчиков.** Реальные цифры (3 подписчика) работают против
  цели. Числа — только про объём и формат работы.
- **Не заявлять сроки, ставки, условия работы** — они не определены.
- **Не выдумывать** отзывы, клиентов, кейсы, публикации, награды, гарантии, годы опыта,
  размер команды, «100+ проектов». Пустое место честнее выдуманного доказательства.
- Не придумывать имя студии, автора, маскота. Имя «Alex» из описания канала не
  использовать — не подтверждено, кто это (`PRODUCT.md`, «Явно не решено»).
- Не утверждать авторство конкретных дисциплин (сценарий / музыка / анимация) — не
  подтверждено.
- Не смешивать две «головы» бренда: 3D-маскот — лицо продукта; реальное фото ребёнка из
  аватара канала на этом сайте **не используется вообще**.
- Русской версии и переключателя языков нет.

## 11. Чего не хватает для сборки

Блокирующее:

1. **Ссылка на WhatsApp** — номер или прямой URL бота. Без неё главная кнопка нерабочая.
   До получения — заглушка `href="#"` с явным `TODO` в коде.
2. **Ссылки на 5 роликов на YouTube** — под карточки галереи. Есть только названия со
   скриншота. Без них галерея некликабельна.

Желательное:

3. Текст, с которым открывается чат в WhatsApp (`?text=`) — например
   `Hi! I'd like to discuss an animated video for our brand.`
4. Подтверждение: показываем 5 роликов, по которым есть обложки, или автор даёт обложки к
   остальным 13. Для галереи из одного экрана 5 карточек достаточно, добор не обязателен.
5. Ссылка на сам канал Kiki Toony — если её ставить, то **только как мелкую подпись в
   микро-ряду внизу**, не кнопкой: она уводит трафик мимо целевого действия.

## 12. Критерий готовности

Сайт готов, когда всё верно:

- [ ] На десктопе (1440×900) страница помещается в один экран без вертикальной прокрутки.
- [ ] На iPhone SE (375×667) — не больше одного экрана прокрутки, CTA виден всегда.
- [ ] На странице **ровно одна** кнопка, и она ведёт в WhatsApp в новой вкладке.
- [ ] Все 5 обложек открываются кликом на свой ролик.
- [ ] Галерея листается мышью-драгом, колесом, свайпом и клавиатурой; обрезана краем экрана.
- [ ] Общий вес страницы < 1.5 МБ, LCP < 2.5 с на 4G.
- [ ] Ни одной цифры про просмотры/подписчиков, ни одного выдуманного факта.
- [ ] Ни одного `#FFFFFF` и `#000000` в CSS.
- [ ] `prefers-reduced-motion` отключает marquee и анимации входа.
- [ ] Текста на странице — меньше 60 слов, весь на английском.
